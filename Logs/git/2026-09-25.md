### fix(backend): 修复知识问答误报401并统一错误响应契约
**Commit**: 0e1dd2c
**分支**: master
**变更文件数**: 5
**代码行数**: +84 / -31

**修改内容：**

**问题根因**
- `POST /api/knowledge/ask` 在 `LLM_USE_MOCK=false` 且外部 LLM 不可达时返回误导性 `code=401`：
  `llm_service` 抛 `RuntimeError` → 被 `login_required` 的 `except Exception` 吞掉 → 误判为「Token无效」

**修复明细**
- `middleware/auth_middleware.py`：`fn()` 移出 try 块，仅捕获 `JWTExtendedException` / `PyJWTError`；
  新增 `_load_user()` 辅助函数；路由内部异常不再被吞成 401
- `app.py`：新增 `@app.errorhandler(Exception)` 兜底 + `404` 处理；500 统一走 `server_error()`
- `services/llm_service.py`：真实 LLM 调用增加 `timeout` 与降级回退 mock，回退时标记 `degraded=True`
- `routes/knowledge.py`：`generate_answer` 包 `try/except (RuntimeError, ValueError)` → `code=502`；
  限流阈值移入 `config`（`KNOWLEDGE_ASK_RATE_LIMIT_PER_MINUTE`），超限由裸 dict+HTTP429 改为 `code=429`；
  补 `not_found` 导入缺失（`/related` 接口原会 NameError）；响应 data 新增 `degraded` 字段
- `config.py`：新增 `LLM_TIMEOUT_SECONDS` / `LLM_FALLBACK_TO_MOCK` / `KNOWLEDGE_ASK_RATE_LIMIT_PER_MINUTE`

**验证结果（实机接口测试，:5000）**
| 用例 | 期望 | 实际 |
|------|------|------|
| 有效 token + 提问（外网 LLM 不可达） | `code=0` | `code=0`，`degraded=true`，sources=3 ✅ |
| 畸形 token | `code=401` | `code=401`（原先返回 HTTP 422 非约定结构）✅ |
| 无 token | `code=401` | `code=401` ✅ |
| 路由内部异常 | `code=500`（非 401） | `code=500 服务器内部错误` ✅ |
| 连续提问超限 | `code=429` | 第 19 次起 `code=429` ✅ |
| `/related` 不存在 id | `code=404` | `code=404 知识不存在` ✅ |

**结论**：`/api/knowledge/ask` 不再出现误导性 401，错误响应契约全链路统一为 `{code, message, data}`。
