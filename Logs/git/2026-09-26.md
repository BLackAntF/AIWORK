### feat(rag): 知识问答真流式输出（SSE + 非流式降级兼容）
**Commit**: c158229
**分支**: master
**变更文件数**: 5
**代码行数**: +329 / -85

**背景**：
- 原 AI 问答为「等完整回答返回后再用打字机模拟」的假流式；用户要求以最小改动实现真正的 LLM 流式输出
- 约束：不改移动端、不破坏既有 `/api/knowledge/ask` JSON 契约、不改动 web 视觉样式

**修改内容：**

**① 后端流式生成（`backend/services/llm_service.py`）**
- 抽出 `_build_messages(question, knowledge_list, detection_context, disease_profile)`：system prompt + user 消息构造，供非流式/流式复用，行为与原有提示词完全一致
- 原 `generate_answer()` 保留，仅改为调用 `_build_messages()`（非流式链路零行为变化）
- 新增 `_stream_mock_answer()`：mock 模式按 4 字符/30ms 逐段产出，末条产出 `meta`（sources/degraded=True）
- 新增 `generate_answer_stream()`：
  - 真实 LLM 走 `client.chat.completions.create(..., stream=True)`，逐 chunk 取 `chunk.choices[0].delta.content` 产出 `{'type':'delta','text':...}`
  - 异常时按 `LLM_FALLBACK_TO_MOCK` 决定降级 mock 或抛 `RuntimeError`；末条产出 `{'type':'meta','sources':[...],'degraded':bool}`

**② 后端 SSE 接口（`backend/routes/knowledge.py`）**
- 新增 `_persist_chat(...)`：统一封装「用户消息 + 助手消息」落库，非流式/流式共用
- 新增 `_stream_answer_events(...)` 生成器：转发 delta 为 SSE（`data: {...}\n\n`），累加完整回答，流结束后落库并发送 `done` 事件（含 answer/sources/session_id/session_title/degraded）
- `POST /api/knowledge/ask` 读取 `stream` 参数；`stream=true` 时返回 `Response(stream_with_context(...), mimetype='text/event-stream', headers={'Cache-Control':'no-cache','X-Accel-Buffering':'no'})`
- 原非流式 JSON 分支保留，仅落库改为调用 `_persist_chat(...)`（响应结构不变）

**③ 前端流式消费（`frontend/src/views/Knowledge.vue`）**
- 新增 `streamAskQuestion(data, { onDelta, onDone })`：`fetch` POST `/api/knowledge/ask`，带 Bearer token，用 `response.body.getReader()` + `TextDecoder` 按 `\n\n` 切分 SSE 事件
- 事件处理：`delta` → 追加内容并实时 Markdown 渲染；`done` → 用完整 answer/sources 收尾；`error` → 抛错触发降级；401 → 清 token 跳登录
- `sendMessage()` 改为 `stream:true` 流式路径，保留：
  - 流式失败时删除临时气泡，回退到 `askQuestion({...data, stream:false})` + 原 `startTypewriterEffect()`
  - 原有会话切换、新建会话、`loadSessions()`、滚动逻辑不变
- 移动端未改动，继续走非流式 `/ask`，兼容性保持
