# 前端统一与功能迭代实施计划（2026-09-25）

## Context

项目「番茄叶片病害智能诊断平台」当前状态：

- 移动端 App v1 的页面层 API 契约问题已修复并 H5 逐页验证通过（commit `dfac727` / `b7553bc`）。
- 用户要求：**YOLO 真实模型接入（原 P0）延后**，先把其余开发功能做完，并把前端优化到"不要那么 AI 味道"。
- 已确认的方向：**以 web 端现有风格为唯一基准做统一**，不另立新风格。

### 决策（已与用户确认）

| 项 | 决策 |
|----|------|
| web 端视觉 | **零改动**。`effects.css` / `theme.css` / `global.css` / `element-plus.css` / `ParticlesBackground.vue` 全部保留，粒子背景、霓虹发光、玻璃拟态、暗色金色主题都不动 |
| web 端功能 UI | 允许**新增**功能控件/页面，但必须复用现有样式类（`glass-card` / `btn-glow` / `glow-border` / `el-*`）以保持原生感 |
| 移动端 | 视觉对齐 web **浅色主题**（`#E07A5F` 及 web 的字号/间距/圆角体系）；**不引入暗色主题**；用真实线性图标替换全部 emoji |
| RAG（Ollama/Chroma/BGE） | **本轮不做**。改为轻量问答增强：引用来源展示 + 打字机输出 + 多轮会话 |
| 新增依赖 | **不新增**重型依赖：导出只做 CSV（`utf-8-sig`），不做 xlsx；不做 SSE |
| 交付 | **分阶段提交**，每阶段独立可验证 + commit + push + 追加 Git 日志 |

### 功能范围

1. **P1 检测结果优化**：批量图片检测、检测结果导出（CSV）、历史记录高级筛选（日期范围/病害类别/置信度/模型版本）
2. **修遗留问题**：`/api/knowledge/ask` 误导性 401、新增病害档案 HTTP 接口（解封移动端病害档案页）
3. **移动端 Phase 6**：下拉刷新覆盖、统一错误处理与加载态、Token 生命周期、去除硬编码地址
4. **站内通知系统**：新模型 + 接口 + web 铃铛/列表页 + 移动端通知页

### 约束（项目规范）

- 后端遵循 `backend-patterns`，前端遵循 `frontend-design`
- 函数 ≤ 20 行、后端加类型注解与 Docstring、无 Magic Value（走 `config.py`）、查询参数化、输入校验、变更类路由加权限装饰器
- 禁止硬编码密钥，沿用 `config.py` 的环境变量模式
- 响应统一 `{code, data, message}`；`utils/response.py::error()` **返回 HTTP 200 + code**，这是全项目既有约定

## 分阶段实施

### Phase 1 — 后端健壮性修复（ask 401 根因）

**目标**：`/api/knowledge/ask` 在外部 LLM 不可达时返回明确业务错误而非误导性 401。

**后端**
- `middleware/auth_middleware.py`：把 `fn(*args, **kwargs)` 移出 try 块；try 内只留 `verify_jwt_in_request()`，且只捕获 JWT 相关异常（`flask_jwt_extended.exceptions.JWTExtendedException` 及其子类）。路由内部异常改为向上冒泡。
- `app.py`：新增 `@app.errorhandler(Exception)`，记录 `logger.exception` 后用 `utils/response.py::server_error()` 返回（HTTP 200 + `code=500`）。**因为 `error()` 本就返回 HTTP 200，web/mobile 现有拦截器都能正确处理，无需改前端。**
- `routes/knowledge.py::ask_question`：把 `llm_service.generate_answer(...)` 包 `try/except (RuntimeError, ValueError)`，失败返回 `error(code=502, message='AI 服务暂时不可用，请稍后重试')`；限流分支由裸 dict + HTTP 429 改为 `error(code=429, ...)`，阈值移到 `config.py`。
- `services/llm_service.py`：`chat.completions.create` 加 `timeout=`；外部调用失败且 `LLM_FALLBACK_TO_MOCK` 为真时记日志并回退 `_generate_mock_answer(...)`，返回值加 `'degraded': True`。
- `config.py`：新增 `KNOWLEDGE_ASK_RATE_LIMIT_PER_MINUTE`、`LLM_TIMEOUT_SECONDS`、`LLM_FALLBACK_TO_MOCK`（均支持 env 覆盖）。

**无 DB 变更 / 无前端改动**

**验证**：`python app.py` → 用 `admin/password123` 取 token → `POST /api/knowledge/ask` 期望 `code=0` 且 `degraded=true`（外网不可达时），**绝不出现 401**；错误 token 仍返回 `code=401`；超限返回 `code=429`；故意触发一个路由内部异常应返回 `code=500` 而非 401。
