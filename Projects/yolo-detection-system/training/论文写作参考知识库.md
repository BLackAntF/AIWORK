## 三、方法模块写法模板

### 3.1 GSConv 写法（公式 + 描述）

**描述模板**（改写自西南大学论文 1.3.2 节）：

> 分组混洗卷积（Group-Shuffle Convolution，GSConv）在将空间信息转化为通道信息的过程中能保持通道之间的隐藏连接，且不会显著增加模型的时间复杂度。GSConv 先通过标准卷积提取部分通道特征，再通过深度卷积处理剩余通道，最后通过通道混洗（channel shuffle）操作实现跨通道信息交互。

**公式**：
- GSConv 全局跨通道信息融合的时间复杂度：
  $$O(H \times W \times C_{in} \times C_{out} \times K^2)$$
- GSConv 稀疏部分计算量：
  $$O(\alpha \times H \times W \times C_{in} \times C_{out} \times K^2)$$
- GSConv 总时间复杂度：
  $$O(H \times W \times C_{in} \times C_{out} \times (1 + \alpha K^2))$$

其中 $H, W, C_{in}$ 为输入特征图尺寸，$\alpha$ 为稀疏率，$C_{out}$ 为输出通道，$K \times K$ 为卷积核大小。

**核心优势表述**：
- 比标准卷积计算成本低约 30%~40%，但学习能力不逊色
- 保持通道间隐藏连接，减少信息丢失
- 不建议全模型使用（会加深网络、增加推理延迟），应只用于 Neck

### 3.2 Slim-Neck 写法

**描述模板**：

> Slim-Neck 通过将 Neck 中的标准 CSP 模块替换为 VoV-GSCSP（Variety of Views-Group Shuffle Cross Stage Partial）模块实现轻量化。VoV-GSCSP 由 GS 瓶颈（GSBottleneck）和跨阶段部分网络（CSPNet）组成，采用一次性聚合（one-shot aggregation）策略，在保持通道间隐藏连接的同时降低网络复杂度和计算成本。替换 Neck 中的标准 CSP 后，FLOPs 可减少约 15.72%。

**Slim-Neck 模块组成**：
1. **GSConv**：替代标准卷积
2. **GSBottleneck**：GSConv 瓶颈结构，含 shortcut 残差连接
3. **VoVGSCSP**：跨阶段部分模块，内部堆叠 n 个 GSBottleneck

**适用位置**：仅替换 Neck（头部）的 C3k2/C2f 模块，保留 Backbone 标准卷积。理由：Neck 处特征图空间维度已小、通道数已达最大，需要更好的特征融合而非复杂转换，此时 GSConv 能减少冗余、提升注意力模块效果。

### 3.3 知识蒸馏写法

**描述模板**（参考 arXiv 2410.12259 + LKD-YOLOv8）：

> 知识蒸馏（Knowledge Distillation，KD）通过让一个轻量化的学生网络（Student）学习一个高性能教师网络（Teacher）的输出分布，在保持学生网络参数量和计算量优势的同时提升其检测精度。本文选用 YOLO26s 作为教师网络，Slim-Neck 改进的 YOLO26n 作为学生网络。教师网络冻结参数，仅更新学生网络参数。蒸馏损失与原始检测损失加权求和作为总损失：
>
> $$L_{total} = L_{det} + \lambda_{dis} \cdot L_{distill}$$
>
> 其中 $L_{det}$ 为原始检测损失（包含分类损失、定位损失、置信度损失），$L_{distill}$ 为蒸馏损失，$\lambda_{dis}$ 为蒸馏损失权重（本文取 6.0）。

**蒸馏损失类型**（根据实际实现选择）：
- **响应蒸馏（Response-based）**：匹配教师和学生检测头的输出 logits 分布。ultralytics 内置蒸馏采用此方式，通过 `dis` 参数控制蒸馏强度。
- **特征蒸馏（Feature-based）**：匹配中间特征图。需要额外的投影层对齐通道数。

**超参说明**：
- 温度 $T$：软化教师输出分布，$T$ 越大分布越平滑。arXiv 2410.12259 实验表明在特定温度下学生模型 mAP 超过原模型。
- 蒸馏权重 $\lambda_{dis}$：平衡蒸馏损失和检测损失。

### 3.4 类别不平衡处理（cls_pw）写法

**描述模板**：

> 番茄病害数据集中各类别样本数量分布不均，少数类（如花叶病毒病）样本量远低于多数类，导致模型对少数类的检测精度偏低。本文采用类别加权（class-positive weight）策略，在分类损失中为不同类别赋予不同权重：
>
> $$L_{cls} = -\sum_{i=1}^{C} w_i \cdot [y_i \log(p_i) + (1-y_i) \log(1-p_i)]$$
>
> 其中 $w_i$ 为第 $i$ 类的权重，根据类别样本频率的倒数设定，使少数类获得更大的损失权重。本文设置 `cls_pw=0.5`，在提升少数类召回率的同时不过度抑制多数类。

**配套策略 close_mosaic**：
> 在训练末期（最后 20 个 epoch）关闭 Mosaic 数据增强，避免增强带来的图像分布偏移影响模型收敛，使模型在真实数据分布上进一步优化。

### 3.5 注意力机制（CBAM）写法（作为对比实验/消融项）

**描述模板**：

> CBAM（Convolutional Block Attention Module）是一种轻量级注意力模块，由通道注意力（Channel Attention）和空间注意力（Spatial Attention）串联组成。通道注意力通过全局平均池化和最大池化生成通道权重，空间注意力通过通道维度的平均池化和最大池化生成空间权重。本文在 Backbone 的 P3、P4、P5 输出后各插入一个 CBAM 模块，以增强模型对病害关键区域的关注。

### 4.2 评价指标模板

> 本文采用精确率（Precision，P）、召回率（Recall，R）、平均精度均值（mAP@0.5）、参数量（Params）和浮点运算量（FLOPs）作为评价指标。
> - **mAP@0.5（主指标）**：IoU 阈值为 0.5 时各类别 AP 的平均值。本文应用场景为整叶病害分类，检测框仅用于定位整片叶片，不要求像素级病斑定位，故以 mAP@0.5 作为定位精度的主要评价指标
> - mAP@0.5:0.95（辅助指标）：IoU 阈值从 0.5 到 0.95（步长 0.05）的 mAP 平均值，完整反映框回归精度。本数据集为整叶标注（框相对面积中位数 74.94%），该指标变化对业务无实质影响
> - Params：模型可训练参数总量，反映模型存储开销
> - FLOPs：模型前向传播浮点运算次数，反映模型计算复杂度

**指标选择依据段（可直接引用）**：

> 考虑到本研究的应用场景，检测结果主要用于判定叶片是否患病及所属病害类别，并作为后续防治建议生成的输入，不涉及对病斑的像素级定位。因此本文以 mAP@0.5 作为定位精度的主要评价指标，同时报告 mAP@0.5:0.95 以完整反映模型性能。

## 十一、系统设计写法

### 11.1 系统总体架构写法

**本系统采用前后端分离的 B/S 架构**，分为三层：

```
┌─────────────────────────────────────────────────┐
│              表现层（前端 Vue 3）                 │
│  Web 端 │ 移动端 H5 │ 管理后台                    │
├─────────────────────────────────────────────────┤
│            业务逻辑层（后端 Flask）                │
│  认证授权 │ 检测服务 │ 知识库服务 │ AI问答服务     │
│  历史管理 │ 样本池   │ 通知服务   │ 统计服务       │
├─────────────────────────────────────────────────┤
│              数据存储层                           │
│  SQLite/MySQL │ ChromaDB向量库 │ YOLO模型权重     │
└─────────────────────────────────────────────────┘
```

**描述模板**：

> 系统采用前后端分离的 B/S（Browser/Server）架构，遵循高内聚低耦合的设计原则。整体分为三层：
> （1）**表现层**：基于 Vue 3 + Element Plus 构建，提供 Web 端和移动端响应式界面，负责用户交互与结果展示；
> （2）**业务逻辑层**：基于 Flask 框架构建 RESTful API 服务，封装认证授权、图像检测、知识库检索、AI 问答、历史管理、样本池等核心业务逻辑；
> （3）**数据存储层**：使用 SQLite/MySQL 存储结构化数据，ChromaDB 存储知识库向量，YOLO 模型权重文件存储于文件系统。
> 前后端通过 HTTP/JSON 进行数据交互，检测模型以服务化方式集成，便于后续模型迭代升级。

### 12.2 关键模块实现写法

#### 12.2.1 图像检测模块实现

> 图像检测模块是系统的核心功能。前端通过 `ImageUpload` 组件接收用户上传的番茄叶片图像，经 axios 发送至后端 `/api/detection/upload` 接口。后端 `yolo_service.py` 服务加载改进 YOLO26 模型权重，对图像进行预处理后执行推理，将检测结果（边界框坐标、类别、置信度）绘制在原图上，并将检测结果以 JSON 格式存入 detection_history 表。前端通过 `DetectionResult` 组件展示标注后的图像和检测详情。

**检测流程图**：
```
用户上传图像 → 后端接收 → YOLO模型推理 → 绘制检测框 → 保存历史记录 → 返回结果
```

#### 12.2.2 知识库与 AI 问答模块实现

> AI 问答模块基于检索增强生成（RAG）技术。知识库条目向量化后存储于 ChromaDB，用户提问时先通过向量检索获取最相关的知识库内容，再将检索结果与用户问题一并提交给通义千问大语言模型，生成结合知识库的回答。对话历史存储于 chat_history 表，支持多轮对话上下文关联。

#### 12.2.3 样本池模块实现

> 样本池模块用于收集用户对检测结果的反馈，支持模型增量训练。用户可对检测结果标记为"正确"、"分类错误"、"漏检"或"不确定"，并提供修正类别。低置信度检测结果自动收录至样本池。管理员审核通过的样本可导出为训练数据，用于下一轮模型微调，形成"检测-反馈-训练"的闭环。

### 12.3 前端实现写法

> 前端基于 Vue 3 + Vite 构建，采用 Element Plus 组件库实现响应式界面。使用 Vue Router 管理页面路由，Pinia 管理全局状态（用户信息、主题、通知等）。核心页面包括：登录/注册页、检测页（Detect.vue）、历史记录页（History.vue）、知识库页（Knowledge.vue）、AI 问答页、个人中心页，以及管理员后台的用户管理、知识库管理、数据统计看板、样本池审核等页面。

### 12.4 后端实现写法

> 后端基于 Flask 框架，采用应用工厂模式（create_app）创建应用实例。通过 Flask-SQLAlchemy 操作数据库，Flask-JWT-Extended 实现身份认证，Flask-CORS 处理跨域。路由按功能模块拆分至 routes/ 目录，业务逻辑封装于 services/ 目录，中间件（middleware/）实现认证、日志等横切关注点。

## 十四、系统章节写作注意事项

### 14.1 图表要求
- 系统架构图：必画，展示三层架构
- 功能模块图：必画，展示模块划分和依赖
- ER 图：必画，展示实体关系
- 用例图：必画，展示参与者和用例
- 界面截图：每个核心功能配 1-2 张截图
- 时序图/流程图：核心流程（如图像检测流程）配流程图

### 14.2 代码展示
- 后端代码：展示核心接口的关键代码片段（如检测接口、AI 问答接口），不超过 30 行
- 前端代码：展示核心组件的关键逻辑（如图像上传、结果展示）
- 代码需加注释，说明关键步骤

### 14.3 与算法章节的衔接
- 第四章（模型改进）的实验结论要在第五章（系统实现）中体现，如"系统集成第四章提出的改进 YOLO26 模型"
- 系统中使用的模型版本、参数量、mAP 等指标要与第四章一致
- 系统检测性能（响应时间）要基于第四章的模型推理速度

### 14.4 避免的问题
- 不要堆砌代码，重点讲设计思路和实现逻辑
- 不要只描述功能，要讲清"为什么这么设计"
- 数据库设计要给出表结构和字段说明，不能只给 ER 图
- 测试部分要有具体数据，不能只写"测试通过"
