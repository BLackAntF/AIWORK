### AI 问答（LLM）配置
- 配置位置：`backend/.env`（已 `.gitignore`，密钥不进仓库）

### 知识库检索（2026-09-25 升级：jieba + BM25 纯本地方案）
- 约束背景：**不用 Ollama、不新增任何 API key**；实测现有 LLM 网关 `8888ok.cc/v1` 无 embedding 模型（仅 deepseek-v4-flash / deepseek-v4.1-flash），`/v1/embeddings` 返回 model_not_found
- 方案：jieba 中文分词 + rank_bm25（`BM25Okapi`），纯 Python 实现，无向量数据库 / embedding 服务 / 本地模型 / 联网依赖
- 依赖：`backend/requirements.txt` 已加 `jieba>=0.42.1`、`rank_bm25>=0.2.2`；代码内 ImportError 容错，缺包自动降级朴素打分
- 检索管线（`backend/services/knowledge_service.py`）：
  - `_DISEASE_TERMS` 领域词典（30+ 病害/防治术语）注册 jieba，病名不被拆散
  - `_SYNONYM_MAP` 同义词映射（口语→专业术语）：叶子→叶片、发黄→黄化、斑点→病斑、打药/用药→药剂、萎→萎蔫 等
  - `_tokenize` → `_expand_synonyms`（保留原词+映射词）→ `_build_corpus`（标题 token 双份加权）→ BM25 打分 → 全 0 分按 `views` 降序兜底
- 测试数据过滤 `_active_knowledge()`：排除 `is_active=False`、category ∈ {测试分类, test, 测试}、title 以 `test%`/`tmp%`/`kb_%` 开头的脏数据
- 效果：旧逻辑（中文整句按空格 split）5 条查询全随机兜底；新逻辑 5 条查询第 1 名全部精确命中对应条目

### 关键约定
- **后端响应格式**：`{ code: 0, data: {...}, message: "..." }`，`code=0` 表示成功（注意不是 200）
- H5 通过 vite 代理把 `/api` 转发到 `:5000`
- 网页端**不实现视频识别**（预留移动端）

## 三、项目规范与约束

**安全红线（必须遵守）**
- 禁止硬编码密钥 / API Key / 密码（用环境变量）
- 所有数据库查询必须参数化；用户输入必须校验
- 禁止 `eval`、字符串拼接 SQL；敏感操作必须权限校验

**工程规范**
- 函数不超过 20 行（单一职责）；用类型注解与 Docstring
- 禁止 Magic Value；第三方库需在白名单内
- AI 生成代码需人工 review，需有单元测试

**角色分工（按项目工作流）**
- 前端任务：用 `frontend-design` skill；后端任务：用 `backend-patterns` skill
- 审查任务：用 `TRAE-code-review` skill，报告存 `Reports/`
- 管理任务：只出报告与提示词、不写代码；负责 Git commit/push + 写日志

**Git 约定**
- 日志写入 `d:\Develop\CODE\AIWORK\Logs\git\YYYY-MM-DD.md`
- 项目文件放 `Projects/`，规范文件放 `Memory/`

**移动端约定**
- 技术栈 uni-app（Vue 3 Composition API + Pinia）
- API 层 `mobile/src/api/*.js` 是权威命名，页面必须与之一致
