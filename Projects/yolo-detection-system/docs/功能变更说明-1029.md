# 功能变更说明（2026-10-29）

> 本轮新增：低置信度兜底、结果分享、天气联动、病害防治结构化字段，以及两处配套代码补全（样本池自动标识、阈值默认配置）。本文档供接口对接、数据库维护与部署参考，所有字段与签名均来自实际代码。

---

## 一、新增 / 变更接口

### 1. 检测接口返回增强（已有接口，返回新增字段）

`POST /api/detect/image`、`POST /api/detect/batch` 的每条结果新增：

| 字段 | 类型 | 说明 |
|------|------|------|
| `low_confidence` | bool | 最高置信度是否低于阈值 |
| `confidence_threshold` | float | 当前生效的低置信度阈值 |
| `top_candidates` | array | 按类别聚合的候选，最多 3 个：`[{class_id, class_name, confidence}]`，按置信度降序 |
| `sample_pool_id` | int\|null | 低置信度自动收录样本池后的记录 ID；未收录为 null |

- 原有字段不变，向后兼容；批量接口与单图共用同一逻辑。
- 阈值读取优先级：`SystemConfig.low_confidence_threshold` > `app.config['LOW_CONFIDENCE_THRESHOLD']`（默认 0.5）。

### 2. 创建分享链接（需登录）

```
POST /api/history/<history_id>/share
Body: { "expires_days": 7, "base_url": "http://localhost:5173" }
```

| 参数 | 必填 | 说明 |
|------|------|------|
| `expires_days` | 否 | 有效期天数，1~30，默认 7 |
| `base_url` | 否 | 前端站点根地址；合法 http(s) 前缀才生效，否则回退请求站点 |

- 仅记录本人或 admin 可分享；同一记录已有未过期链接则复用。
- 响应：`{ token, share_url, expires_at, qr_code }`，`qr_code` 为 base64 PNG（前端拼 `data:image/png;base64,`）。

### 3. 公开访问分享结果（免登录，只读）

```
GET /api/share/<token>
```

- 无需登录，不暴露用户名/邮箱等隐私。
- 响应：`{ history, detections, expires_at }`，`detections` 中每条附 `disease_profile`（含新增防治字段）。
- 错误：无效 token 返回 404「分享链接不存在或已被删除」；过期返回 410「分享链接已过期」。

### 4. 天气与施药建议（免登录）

```
GET /api/weather?lat=<纬度>&lon=<经度>
```

| 参数 | 范围 | 说明 |
|------|------|------|
| `lat` | -90~90 | 纬度，超出返回 400 |
| `lon` | -180~180 | 经度，超出返回 400 |

- 代理 Open-Meteo（免费、无需 Key），30 分钟内存缓存。
- 响应：`{ current: {temperature, humidity, precipitation, weather_code, wind_speed}, daily: [{date, weather_code, temperature_2m_max, temperature_2m_min, precipitation_probability_max}], advice: {suitable, reason} }`。
- 施药建议：未来 24h 降水概率 >60% 或当前风速 >5 m/s → `suitable=false`；否则 `true`。
- 网络异常返回 `server_error('天气服务暂不可用')`，不抛堆栈。

### 5. 管理端病害档案写接口（admin）

```
PUT /api/admin/disease-profiles/<profile_id>
Body: 任意可写字段
```

可写字段：`disease_name`、`causes`、`symptoms`、`occurrence`、`prevention`、`treatment`、`pesticides`、`dosage`、`safety_interval`、`biological_control`、`is_active`（布尔）。未提供可写字段返回 400。操作计入管理审计日志。

## 二、数据库变更

### 1. 新增表 `share_links`

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | Integer PK | 自增 |
| `token` | String(64) | 唯一索引，分享令牌 |
| `history_id` | Integer FK→detection_history.id | 关联检测记录，索引 |
| `user_id` | Integer FK→users.id | 创建者，索引 |
| `expires_at` | DateTime | 过期时间（UTC） |
| `created_at` | DateTime | 创建时间（UTC），索引 |

### 2. `disease_profiles` 新增列

| 字段 | 类型 | 说明 |
|------|------|------|
| `dosage` | Text | 用药剂量 |
| `safety_interval` | String(100) | 安全间隔期 |
| `biological_control` | Text | 生物防治 |

### 3. `sample_pool` 新增列

| 字段 | 类型 | 说明 |
|------|------|------|
| `auto_created` | Boolean | 是否低置信度自动收录，默认 false，索引 |

**迁移方式**：SQLite 的 `db.create_all()` 不会为已存在的表补列。启动时 `_migrate_added_columns()` 用 `PRAGMA table_info` 检查缺失列并 `ALTER TABLE` 补齐（幂等，仅 SQLite 生效）；`share_links` 新表由 `db.create_all()` 自动创建。

## 三、部署变更

| 项 | 说明 |
|----|------|
| 新增依赖 | `qrcode>=7.4.2`（生成分享二维码），已加入 `requirements.txt`，需 `pip install` |
| 新增配置 | `LOW_CONFIDENCE_THRESHOLD`（环境变量，默认 0.5）；管理端「系统配置」可见可改 |
| 默认配置入库 | 启动时 `_ensure_default_configs()` 幂等插入 `low_confidence_threshold=0.5`，使配置页可编辑 |
| 重启生效 | 需重启后端以执行列迁移、创建 `share_links` 表、插入默认配置 |
| 前端路由 | 新增公开路由 `/share/:token`（免登录，守卫放行）；生产部署需保证 `/share/*` 指向前端应用 |
