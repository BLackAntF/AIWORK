## 三、P1：模型对比分析（论文/毕设核心章节）

| # | 事项 | 产出 |
|---|------|------|
| 1 | 逐轮指标对比 | 基线 vs Slim-Neck 的 mAP50 / mAP50-95 / P / R 曲线（同一坐标轴） |
| 2 | 最佳轮次对比 | 各自 best epoch 及对应指标 |
| 3 | 效率对比 | 参数量、GFLOPs、单轮耗时、推理速度（FPS，需实测）、权重文件大小 |
| 4 | 分类别对比 | 10 类病害的 AP 差异，找出 Slim-Neck 对哪些类别更友好/更差 |
| 5 | 结论与决策 | 是否替换线上模型；若替换，走替换+复测流程 |
| 6 | 撰写实验报告 | `docs/Slim-Neck实验报告-对比分析.md`，数据全部引用溯源文档 |

**决策标准（预先约定，避免事后找理由）**：
- 精度：mAP50 下降 ≤ 0.3% 视为"精度持平"；> 0.3% 视为"精度下降"
- 效率：参数量/GFLOPs 已确认下降约 4.5% / 9.7%
- 若"精度持平 + 效率提升" → 可替换；若"精度明显下降" → 保留基线，Slim-Neck 作为对比实验结论

### 6.3 明确排除的方向

- 无人机/UAV 影像分析（需额外硬件）
- ESP32/Arduino 自动喷施、IoT 大棚传感器（需硬件）
- Azure Custom Vision / Groq Llama Vision / Gemini 等付费推理服务（需付费账号）
- 推理后端可插拔、MLOps/TF Serving（对当前单体 Flask 架构收益低，改造成本高）

### 6.4 落地方案

**第一批（低成本、可直接做）**：结构化防治方案 + 低置信度兜底进样本池 + 分享二维码 + 天气联动。

**第二批（需设计）**：严重度分级（涉及算法与报告改版）、地块病程跟踪（涉及数据模型重构）。

**暂不做**：视频/摄像头实时检测——与"Web 端不做视频识别"的既定约束冲突，留待 App 阶段决策。

```
现在
 ├─ 训练在跑（约 4.8h，无需人工干预）
 ├─ 并行做：P1 技术债（TODO.md 同步、Stats.vue 修复）  ← 本地即可完成

 │
训练结束
 ├─ 拉回产物 → 对比分析 → 输出实验报告
 ├─ 决策：是否替换线上模型
 └─ 关闭 AutoDL
 │
之后
 ├─ 真机打包回归
 └─ 按调研结果排功能借鉴（先做低成本高价值的）
```

**关键原则**：
1. 训练跑完前不动线上模型，避免线上与实验混淆。
2. 所有对比数据必须能追溯到 `records/` 或 `runs/` 中的原始文件。
3. 功能借鉴先评审再动手，避免堆功能导致维护成本失控。
