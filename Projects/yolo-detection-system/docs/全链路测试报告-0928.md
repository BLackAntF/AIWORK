## 二、本轮修复清单

### 缺陷 1 · Web 管理端「检测记录」顶部统计恒为 0

- **现象**：`/admin/detections` 顶部“总检测数 / 今日检测”显示 0，但表格“共 39 条”。
- **根因**：后端 `/api/admin/detections/stats` 返回字段为 `total`、`today`，前端读取 `stats.total_count`、`stats.today_count`，字段名不匹配。
- **修复**：[Detections.vue](file:///d:/Develop/CODE/AIWORK/Projects/yolo-detection-system/frontend/src/views/admin/Detections.vue#L11-L15) 绑定改为 `stats.total` / `stats.today`，异常兜底对象键名同步修正。
- **验证**：接口实测 `{"avg_processing_time":0.21,"today":0,"total":39}`，页面将正确显示“总检测数 39”。

### 缺陷 2 · 移动端 H5 首页「累计检测」统计口径错误

- **现象**：首页“累计检测”恒为 5；病害/健康数量也只基于最近 5 条。
- **根因**：[index.vue](file:///d:/Develop/CODE/AIWORK/Projects/yolo-detection-system/mobile/src/pages/index/index.vue) 用 `getHistoryList({ page:1, page_size:5 })` 返回的 `records.length` 当总数，未使用真实全量统计。
- **修复**：
  - 后端新增 `GET /api/history/stats`，返回当前用户全量 `{ total, disease_count, healthy_count }`，口径：无检出目标只计入累计；全部为健康类别计入健康，否则计入病害（[history.py](file:///d:/Develop/CODE/AIWORK/Projects/yolo-detection-system/backend/routes/history.py#L206-L236)）。
  - 移动端新增 `getHistoryStats()`（[history.js](file:///d:/Develop/CODE/AIWORK/Projects/yolo-detection-system/mobile/src/api/history.js#L11-L14)），首页三项统计改由该接口驱动。
- **验证**：接口实测 `{"disease_count":34,"healthy_count":1,"total":35}`；首页将显示 累计检测 35 / 检出病害 34 / 健康叶片 1。

### 缺陷 3 · 移动端 H5 首页检测记录病害名与状态异常

- **现象**：首页“最近检测”列表恒显示文件名与“待查看”，病害名与健康/需关注状态不生效。
- **根因**：`/api/history` 列表接口 `to_dict(include_detail=False)` 不返回 `detections` 字段，而页面 `getDiseaseName`/`isHealthyRecord`/`getStatusLabel` 依赖 `record.detections`。
- **修复**：[index.vue](file:///d:/Develop/CODE/AIWORK/Projects/yolo-detection-system/mobile/src/pages/index/index.vue#L165-L191) 三个函数改用列表实际返回的 `class_names` 字段判断（健康类别：健康 / 健康叶片 / 健康叶子 / 正常叶片 / Healthy）。

### 缺陷 4 · AI 会话标题乱码（`??????????`）

- **现象**：Web 与 H5 问答页会话列表出现大量 `??????????` 标题。
- **根因**：属历史测试脏数据 —— 早期用工具提交问题时编码异常，中文被写成 `?` 占位（如 `speed-test`、`test-session-verify` 会话）。数据库实测真实中文会话（如“番茄叶斑病怎么防治？”）存储完全正常，**标题生成逻辑本身无缺陷**。
- **修复**：`/api/knowledge/sessions` 增加会话列表过滤（与知识库 `_exclude_test_data` 同思路，非破坏性、不删数据），过滤规则见 [knowledge.py](file:///d:/Develop/CODE/AIWORK/Projects/yolo-detection-system/backend/routes/knowledge.py#L18-L35)：
  - 跳过测试脚本会话 ID（`speed-test`、`test-session-verify`）；
  - 跳过不含中文、且问号 ≥ 3 的乱码标题（兼容 `?????(??? 92.3%)` 这类混合乱码，正常英文标题只有单个问号不会被误伤）。
- **验证**：接口复测会话数 51 → 50，`GARBLED_LEFT=0`，列表仅剩正常中文标题。

### 缺陷 5 · Web 管理端「系统配置」页 No Data（前序修复）

- **根因**：后端 `/admin/config`、`/admin/models` 返回裸数组，前端读取 `res.configs` / `res.models`。
- **修复**：[Config.vue](file:///d:/Develop/CODE/AIWORK/Projects/yolo-detection-system/frontend/src/views/admin/Config.vue) 改用 `Array.isArray(res) ? res : []` 与 `res || []`。
- **验证**：页面正常显示 5 条系统参数 + 1 个默认模型。

### 缺陷 6 · Web 管理端「操作日志」页 No Data（前序修复）

- **现象**：顶部显示“共 13 条”，表格却为空。
- **根因**：后端返回 `{ logs, total }`，前端读取 `res.list`。
- **修复**：OperationLog.vue 改为 `res.logs || []`、`res.total || 0`（[OperationLog.vue](file:///d:/Develop/CODE/AIWORK/Projects/yolo-detection-system/frontend/src/views/admin/OperationLog.vue)）。
- **验证**：13 条日志正常渲染。

> 前序已修复并复验：数据看板统计字段、知识库列表/标签、标签筛选、相关推荐脏数据、分类列表、趋势图表等。
