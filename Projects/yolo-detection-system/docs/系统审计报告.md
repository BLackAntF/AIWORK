## 5. 已确认缺陷与缺口

### BUG-01：知识卡片跳转路径与路由注册不一致

- **状态**：运行时已复现。
- **现象**：点击知识卡片进入 `/knowledge-detail/16`，主内容区域空白；直接访问 `/knowledge-list/16` 能正常显示详情。
- **代码证据**：
  - `frontend/src/views/KnowledgeList.vue:297-299`：`goToDetail()` 跳转 `/knowledge-detail/${id}`。
  - `frontend/src/router/index.js:48-51`：实际注册的是 `/knowledge-list/:id`，未注册 `/knowledge-detail/:id`。
- **影响**：用户通过知识库正常入口无法打开详情，属于核心链路缺陷。
- **截图**：`audit-06-knowledge-card-click.png`、`audit-07-knowledge-detail-direct.png`。

### BUG-02：个人中心统计请求参数和响应字段均与后端不一致

- **状态**：运行时已复现。
- **现象**：新账号当天完成 1 次图片检测后，个人中心显示“总检测次数 1、今日检测 0、图片检测 0”；管理员账号也表现为总数非零、两个分项为零。
- **代码证据**：
  - `frontend/src/views/Profile.vue:320-324`：请求使用 `pageSize`，读取 `res.items`。
  - `frontend/src/views/Profile.vue:325-341`：`total` 直接取 `res.total`，今日和图片数量依赖 `list` 计算。
  - `backend/routes/history.py:173-203`：分页参数为 `page_size`，返回字段为 `list`、`total`、`page`、`page_size`。
- **根因**：`pageSize` 未被后端分页解析读取；响应没有 `items`，导致 `list` 恒为空。`total` 因独立读取而未受影响。
- **截图**：`audit-15-profile-stats-bug.png`。

### BUG-03：管理端知识分类新增、编辑、删除为假成功/占位操作

- **状态**：代码明确确认。
- **代码证据**：
  - `frontend/src/views/admin/Knowledge.vue:743-754`：新增只显示“分类添加成功”并重新拉取，未调用新增 API。
  - `frontend/src/views/admin/Knowledge.vue:756-758`：编辑只弹出信息提示。
  - `frontend/src/views/admin/Knowledge.vue:760-765`：删除只显示“删除成功”并重新拉取，未调用删除 API。
  - `frontend/src/views/admin/Knowledge.vue:422-427`：导入分类 API 的只有 `getCategories`，没有新增、更新、删除函数。
  - 真实前端 API 已存在于 `frontend/src/api/admin.js:94-110`。
  - 真实后端 API 已存在于 `backend/routes/admin/knowledge.py:291-385`。
- **影响**：界面提示成功但数据库不会按操作变更，属于管理端数据一致性与误导性反馈问题。

### BUG-04：操作日志描述、级别和级别筛选的前后端契约不一致

- **状态**：运行现象与代码均确认。
- **代码证据**：
  - `frontend/src/views/admin/OperationLog.vue:87-99`：表格读取 `description` 和 `level`。
  - `frontend/src/views/admin/OperationLog.vue:133-139,193-208`：筛选条件发送 `level`。
  - `backend/models.py:280-292`：日志序列化返回 `detail`，没有 `description` 或 `level`。
  - `backend/routes/admin/__init__.py:13-55`：支持 action、target_type、keyword、日期筛选，没有读取或过滤 `level`。
- **影响**：操作描述和级别列无法正常展示；级别筛选不会生效。
- **截图**：`audit-12-operation-logs.png`。

### BUG-05：关联知识切换时详情和收藏状态可能保持旧数据

- **状态**：静态代码确认，本轮未单独复现点击序列。
- **代码证据**：
  - `frontend/src/views/KnowledgeDetail.vue:164-185`：详情按当前 `route.params.id` 加载。
  - `frontend/src/views/KnowledgeDetail.vue:201-203`：关联推荐跳转另一个 `/knowledge-list/${id}`。
  - `frontend/src/views/KnowledgeDetail.vue:216-250`：收藏状态与详情都只在 `onMounted` 加载。
  - 文件未使用 `watch` 或 `onBeforeRouteUpdate` 监听参数变化。
- **影响**：同一路由记录仅参数变化时 Vue 会复用组件，当前实现不会重新加载新 ID 的详情和收藏状态。

### BUG-06：用户角色变更日志中的“旧角色”记录错误

- **状态**：静态代码确认；角色变更本身本轮未执行。
